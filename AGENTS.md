# NixOS Config

> **Keep this file current.** Update the relevant section when changing aspects, hosts, Den patterns, or flake layout.

## Safety

- NEVER run `nixos-rebuild switch` or `nixos-rebuild boot`
- Validate with `nix flake check` or bounded system-derivation evaluations below. Never evaluate full host attrsets or hosts in parallel: recursive module values can overflow or exhaust resources.
  ```sh
  timeout --signal=TERM --kill-after=5s 45s nice -n 10 nix eval --raw .#nixosConfigurations.WeebMachine.config.system.build.toplevel.drvPath
  timeout --signal=TERM --kill-after=5s 45s nice -n 10 nix eval --raw .#darwinConfigurations.Astraeus.config.system.build.toplevel.drvPath
  ```
- Never touch: `secrets/` `assets/`
- Never delete a file without asking first
- Run `git add -A && git commit` before making large changes
- Push only when explicitly requested for the current task; prior requests or requests for a clean/committed tree do not authorize pushing.

## Flake Management

[flake-file](https://github.com/vic/flake-file) generates `flake.nix`; never edit it manually. `inputs.import-tree ./modules` discovers all `.nix` files recursively.

- **Add/change a flake input:** edit `modules/inputs.nix` (or the relevant aspect file using `flake-file.inputs`)
- **Regenerate flake.nix:** `nix run .#write-flake`

## Den API — Non-Negotiable Rules

- Never use deprecated `den.ctx`; use `den.aspects`, `den.schema`, `den.default`, and `den.policies`.
- Home Manager wiring is automatic with user `classes = ["homeManager"]` and the `home-manager` input. Do not manually import its NixOS module or set `home-manager.useGlobalPkgs`/`useUserPackages`.
- `inputs` is a module argument everywhere — no `specialArgs` needed.
- Flat-form class module arguments **must** include `...` (see below), or evaluation crashes.

## Aspect File Structure

Every aspect uses the attrset form (not dot-chained assignments):

```nix
{ den, inputs, ... }:
{
  den.aspects.foo = {
    nixos = { host, config, pkgs, lib, ... }: { ... };
    darwin = { host, config, pkgs, ... }: { ... };
    homeManager = { host, config, pkgs, ... }: { ... };
    includes = [ den.aspects.bar ];
  };
}
```

- Omit unused blocks; keep class blocks ordered `nixos`, `darwin`, then `homeManager`.
- Alphabetize set-like includes/package/app/cask lists unless order is semantic. Keep baseline profiles before host overrides; preserve intentional precedence/grouping.
- OS class blocks are platform-specific. Guard platform-only Home Manager settings with `pkgs.stdenv.hostPlatform.isLinux`/`isDarwin`; shared aspects must evaluate on both. Reserve `host.class` for schema/policy or imports resolved before `pkgs` exists.

## Batteries — All Opt-In

| Battery | What it does | Where to include |
|---|---|---|
| `den.batteries.define-user` | sets the host user's OS account and Home Manager home path | `setup.nix` → `den.default.includes` |
| `den.batteries.hostname` | sets `networking.hostName` from `host.hostName` | `setup.nix` → `den.default.includes` |
| `den.batteries.primary-user` | NixOS wheel + networkmanager groups; Darwin `system.primaryUser` | `aspects/user.nix` → user aspect `includes` |
| `den.batteries.user-shell "fish"` | fish shell at OS + HM level | `aspects/user.nix` → `den.aspects.weeb` and `den.aspects.nolan` |
| `den.batteries.host-aspects` | wires host-named aspect to its host | `aspects/user.nix` → `primaryUser` |

Do NOT manually declare a host user's `users.users.<name>` account, `home.username`, `home.homeDirectory`, or a battery-owned shell — batteries own these.
`den.aspects.primaryUser` is the shared aspect for `primary-user` and `host-aspects`; both `weeb` and `nolan` consume it and the Fish user-shell battery.

## Profiles (`modules/aspects/profiles/`)

- `base`: portable Home Manager tools, terminals, Git, file management, and monitors; excludes storage, desktop services, Darwin casks, and personal apps.
- `nixosBase`: NixOS cache, locale, and optimization policy.
- `nixosStorage`: Disko/Btrfs/impermanence and rollback for the existing NVMe/LUKS/Btrfs layout; not a generic server profile.
- `nixosSecurity`: persistence-backed identity/security; requires compatible storage for its `environment.persistence` declarations.
- `linuxDesktop`: Linux Home Manager desktop settings plus NixOS services/packages. Blender and Rofi belong here rather than `base`.
- `workstation`: `base` plus personal apps, development, gaming, AI, browser, communication, VPN, and editors; opt-in for servers.

Select profiles explicitly; `base` is not a complete host. Standalone Linux Home Manager also needs platform guards; the external OS supplies services/compositor.

Storage contracts:

- Initrd embeds `scripts/rollback-btrfs.sh`: `archived-<epoch>-<counter>` recovery subvolumes retain 30 days; recognized legacy mtime names get a fresh 30-day grace period. Never clean unknown names, ordinary directories, or symlinks.
- `impermanence` runs `scripts/persistent-storage-report.py` monthly as the host user, read-only on `/persistent`. Compare declarations/live bindings, flag incomplete scans, exclude protected directories/symlinks; missing mounts are not orphans. Never delete data; sizes cover readable metadata only.
- Report JSON history/text persist in `/var/lib/persistent-storage-report` (`0700`, files `0600`). Linux Home Manager shows each summary once in Fish using persisted universal variables.

## Feature Ownership and Exceptions

- Fish configuration is Home Manager-owned; Linux persistence is NixOS-only. The Den battery owns Darwin `/etc/shells`; activation reconciles the existing admin user's login shell. Do not duplicate battery settings.
- Git is Home Manager-owned, including platform-derived `safe.directory`; Linux `.config/gh` persists with mode `0700`. Shared keyring persistence belongs to `security.general`.
- `dev` owns portable HM tools/NixOS integration and idempotently creates mutable `~/projects`. Its Darwin block declares the sole Xcode MAS install; Darwin HM supplies explicit `astraeus-dev-setup` (license-gated first launch, opt-in native runtime download, shared verified iPhone/iPad reuse). No Apple setup/download runs at activation. Android/Flutter/NDK/JDK and any CocoaPods remain project-scoped; see the Mac handoff. Linux shell/user-service variables select system certificates for uv, Nix-patched certifi, and environment-aware Requests. Restart existing processes; independent TLS stores remain separate.
- `workstation.homeManager` owns personal apps/CLI packages; Linux system packages belong to role profiles. `unstable.filen-desktop` is currently commented out.
- Ghostty uses Home Manager `ghostty` on Linux and `ghostty-bin` on Darwin. LocalSend is shared Home Manager; firewall/persistence are NixOS-only.
- Matugen themes, Qt/QML paths, desktop entries, and persistence remain Linux-guarded or NixOS-only. ONLYOFFICE and Celluloid have no declared Mac replacements. A separate Apple Command Line Tools install is unnecessary with Xcode; cross-host synchronization remains deferred.

### Blender

- `linuxDesktop` includes `blender`; Linux HM owns the sole wrapped `pkgs.unstable.pkgsRocm.blender`. Preserve HIP/ROCm and the executable/desktop entry. Python `requests` is already included; inspect dependencies before adding `withPackages`.
- Pin the `ahujasid/mcp-for-blender` add-on, server, and complete Codex plugin together. The plugin owns the sole MCP registration; do not duplicate it in `programs.mcp` or Codex `settings.mcp_servers`.
- Codex requires a real upstream-version directory matching the plugin manifest. Link the HM/XDG-derived cache root to a store tree with that real directory and a `default` symlink alias; give Home Manager the `default` identity so its cleanup skips the alias and normal HM links handle upgrades/rollback/removal. Never force caches or recursively delete them. Refuse real legacy directories/dangling links; verify the guard precedes **both** `cleanCodexPluginCache` and `writeBoundary` so cleanup cannot delete user data first.
- `scripts/blender-mcp-startup.py` uses a persistent one-shot timer, verifies resolved/loaded add-on paths, reports failing phases, and saves preferences only for enablement/privacy changes. Report conflicting user add-ons without overwriting them. Upstream auto-starts the loopback socket. Skip bootstrap for background/`--factory-startup`; never save factory defaults over preferences.
- Disable telemetry/update checks; supply upstream's missing telemetry config without endpoints/keys. Enable MCP code-tool validation (not a sandbox). No generation providers, API keys, firewall rules, or Darwin configuration.
- Persist `.config/blender` and `.local/share/blender`; caches/captures stay ephemeral. Optional focused lifecycle check: `scripts/blender-mcp-smoke-test.py --cache-only` (disposable Home Manager/Codex fixtures; pass generated `home-files`, plugin-cache, and activation paths; rerun after Codex or Home Manager version changes). Full Blender/MCP integration uses disposable profiles and requires a GUI plus free port 9876.

### Homebrew, gaming, and VPN

- `nix-homebrew` bootstraps ARM `/opt/homebrew`; nix-darwin uses cleanup `uninstall`, mutable taps, and native updaters. Features declare casks through module merging, separate from Nix app links/MAS.
- `gaming` is included once through `workstation`. Shared Home Manager owns `pkgs.prismlauncher` and Java runtimes; do not add a Prism cask. Linux Heroic uses NixOS `pkgs.warm.heroic`; Steam, ProtonPlus, compatibility tools, persistence, and `ntsync` stay NixOS-only.
- `gaming.darwin` owns `crossover`, `heroic`, `notprotonnot/notproton/notproton`, and `steam` casks; do not duplicate CrossOver/Heroic through Nix. NotProton uses the upstream `notprotonnot/notproton` tap without a post-install script; approval/runtime setup is manual. Steam requires Rosetta; CrossOver activation remains private user state.
- `gaming.darwin` also declares Wuthering Waves (`6475033368`) through `programs.mas.packages`; the host owns MAS enablement and cleanup policy.
- `proton` owns Linux `pkgs.proton-vpn` and Darwin `protonvpn`. WeebMachine persists `.config/Proton`; caches/logs are ephemeral, keyring/NetworkManager persistence stays in security aspects. Valve Proton belongs to `gaming`; Proton Pass is not declared.

### Linux system policy

- `optimizations.nixos`: one Zstd Zram device capped at 8 GiB or half of RAM; no disk swap, writeback, hibernation, or swappiness override.
- `printing` persists `/var/lib/cups`. With AppArmor, it adapts Avahi's packaged policy to Nix-store paths, selects it on the service, waits for the policy loader, and restarts on policy changes while retaining upstream sandboxing.
- `security.general` blacklists Comodo AAA Services root and emSign G3/C1/C3 for CVE-2026-111943 using the upstream NixOS labels; retain the distrust policy across rollbacks until the selected package set supplies it.
- `security.general` enforces `nixos-ping` on the Nix-store iputils executable behind the capability wrapper. Packaged profiles are parser includes, not loaded policies; broader confinement needs compatibility and denial tests.
- `security.systemd`: coredumps limited to 1 GiB total, per dump, and processing; seven-day mtime retention. Preserve other upstream tmpfiles rules; unexpected upstream coredump-rule changes must fail the build for review.

## Adding Aspects or Hosts

- **Aspect:** create `modules/aspects/<name>.nix` using the structure above. Use HM for portable user settings and OS classes for system integration. Include it in the narrowest profile or host; keep `base` portable. Declare new inputs with `flake-file.inputs` and regenerate the flake.
- **Host:** create `modules/aspects/hosts/<hostname>/<hostname>.nix` (plus `hardware.nix` for NixOS as needed). Declare `den.hosts.<system>.<Hostname>.users.<name> = {}` and a matching host aspect with explicit role profiles and host overrides.
- Update this file for new hosts, patterns, or platform-specific behavior.
